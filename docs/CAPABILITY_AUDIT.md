# MGA 能力现状审计报告

> 审计时间：2026-09-04 12:0x
> 判定方式：**只认落盘产物和跑过的证据**，不看代码里写了什么。
> 三档定义：
> - **真接通** — 有产物文件或跑通过的实测输出
> - **代码层面** — 代码存在但默认关闭 / 从未验证 / 效果未测
> - **没做** — 链路断的，或依赖不满足

---

## 一句话结论

**原创核心（预判帧 System1）是真跑通的，实证充分。其余多数模块是"骨架在、血没通"——尤其"多模态大脑"这条主线实际是断的：训练脚本默认丢弃视觉特征，合规训练数据只剩 3 条。**

## 逐项清单

### ① 感知层（能不能看见屏幕）

| 能力 | 判定 | 证据 / 说明 |
|------|------|------------|
| 真实屏幕截图 | ✅ 真接通 | `blobs/shots/` 1506 张真实截图 |
| GUI 元素检测 | ✅ 真接通 | `ScreenParserBackend`，本地权重 `blobs/weights/screenparser/best.pt` (153MB) + HF `docling-project/ScreenParser` |
| 文字识别 OCR | ✅ 真接通 | `OCRBackend`，跑过 A/B：融合 UIA 后噪声 30%→7% |
| 无障碍树 UIA | ✅ 真接通 | `UIALocator`，零误差读控件 Name+bbox（但不落盘训练，仅运行时兜底） |
| **视觉语义编码** | ⚠️ **代码层面** | `RealScreenEncoder` 懒加载真模型，**失败即降级成"像素哈希特征"**。所以落盘 `X_visual` 非空 ≠ 拿到语义特征，需实测确认真机走的是哪条分支 |

> 直白说：**能看见屏幕上的按钮和文字**（检测+OCR+UIA，这是真的），但**"理解"这一层很弱**——主干只有 MiniMind 26M。

## 三个最该修的断点（按 ROI 排序）

1. **训练丢弃视觉特征** → `train_minimind.py` 加 `--keep-visual` 并接进数据集，让 X_visual 真正参与训练。
   *这是"多模态大脑"从假的变真的唯一开关。*
2. **训练数据只剩 3 条** → 跑一次合规长采（§2.1 命令，≈7.2s/帧，半小时 250 条）。
   *没有数据，修 1 也没用。*
3. **System1 未接进主链路** → 现在 System1 只活在 dino demo 里，主采集链（main.py）完全没用它。
   *你最核心的创新，目前没在正主上跑。*

## 直接回答你的两个问题

**Q：到底能不能识别屏幕？**
能识别（截图 + GUI 检测 + OCR + 无障碍树都是真跑通的），但**不理解**——大脑只有 26M，且视觉特征从没进过训练。

**Q：能不能 computer use？**
**骨架有、护栏有、但从没真跑过**（默认 `dry_run=True` + `auto_execute=false`）。
像 Claude Computer Use 那种"看任意软件→理解→操作"的通用能力，**不具备，也不该现在做**——你自己的硬约束就是做窄它。
