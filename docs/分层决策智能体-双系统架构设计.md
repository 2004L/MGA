# 基于 Computer-Use 的分层决策智能体（双系统架构）

> 目标：以 computer-use 范式构建分层决策智能体，**两阶段推进**——
> Phase 1 先通关简单的小恐龙（chrome://dino），Phase 2 扩展至复杂游戏 GTA5。
> 双系统模拟真实大脑：**System1 小模型**负责基于历史经验的快速决策与即时执行（低延迟）；
> **System2 高层大脑**负责快速推理思考、情景规划，并把经验与记忆**持久化写入存储**。
> 整体由 LLM 主导宏观决策，System1 与 System2 协同形成「感知 → 决策 → 执行 → 学习」完整闭环。

日期：2026-09-06 · 代码：`src/agent/` + `src/demo_dino_agent.py`

## 二、模块与职责

| 文件 | 层 | 职责 |
|---|---|---|
| `agent/game_adapter.py` | 感知/游戏接口 | `GameAdapter` 抽象；`DinoAdapter`（Phase1 已实现）；`GTA5Adapter`（Phase2 占位） |
| `agent/system1.py` | System1 | 物理基线(MotionModel ETA) + **习得残差(LearnedResidual)** + 经验检索 → 逐帧快决策 |
| `agent/system2.py` | System2 | LLM 推理 + 情景规划 + **经验持久化写入** + 纠正回流训练 S1 |
| `agent/memory.py` | 记忆 | 包 `memory_system.MemorySystem`（sqlite，频次×时间衰减×重要性，含 validity 降权） |
| `agent/executor.py` | 执行 | 窗口聚焦 → SendInput 注入 → 画面差异回执自检 |
| `agent/orchestrator.py` | 编排 | 逐帧 S1 → 升级 S2 → 执行 → 校验 → 死亡/重开 → 学习 |
| `demo_dino_agent.py` | 入口 | Phase1 CLI |

### System1「小模型」的三层叠加（关键：不是纯物理）

1. **物理基线**：`MotionModel` 纯数学估 `vx → ETA`（零神经网络，µs 级）。
2. **习得残差**：`LearnedResidual`（RLS 在线学习）。System2 的每条纠正回流训练它 →
   预测"触发时机补偿量"。**解析物理为基，习得残差为进化**——这就是"小模型"。
3. **经验检索**：命中历史经验 → 置信度拉满、直接快决策（像人的"本能"：见过就会）。

### System2「大脑」的三件事

1. **快速推理**：结合局面 + 检索到的历史经验，输出 `{action, react_delta, reason}`（强制 JSON）。
2. **情景规划**：把后续是否紧跟障碍（pair）、速度档位纳入提示词，不只盯最近一个障碍。
3. **经验持久化**：写入 sqlite 经验库；同时把 `react_delta` 蒸馏进 System1 的残差。
   → **下一次同类情形 System1 自己就会**（S2 思考 → 固化为 S1 习惯）。

### 学习闭环（类脑）

```
首次遇到情形 → S1 经验未命中 → escalate
             → S2 思考 + 写经验 + 训练 S1 残差
             → 之后同类情形：S1 经验命中 → 本能快决策（S2 不再被吵醒）
             → 若仍失败：memory.challenge(success=False) 把该经验降权（反经验主义）
```

## 三、Phase 1 验证结果

### 沙箱自测（`--sim --frames 400 --reset-memory`）

```
S1=400(100.0%)  S2=1(0.2%)  经验写入=1  经验命中=202  撞死=0
System1 习得残差样本数=1
```
→ 首次遇到 `cactus|v2|solo` 时 S2 被唤醒 1 次；此后 **202 次全部由 S1 用经验快决策**，S2 再未唤醒。类脑学习闭环成立。

### 真机（chrome://dino，2500 帧，游戏可见时）

```
定位=(725,1014,1110,150)  回执自检 画面差异=21.22 → 按键有效
S1=2497(99.9%)  S2=0  经验命中=162  撞死=3  重开=3
```
另一局（清空经验库）：S2 唤醒 1 次写经验 → 之后 17 次经验命中；该经验在死亡后被标记 `contested`（降权）。

### 修复的问题（真机暴露）

| 问题 | 根因 | 修复 |
|---|---|---|
| **迟到的无效跳**：日志出现 `ETA=-0.408s → jump` | 已越过恐龙的障碍 ETA 为负，仍满足 `eta<react` | System1 过滤 `eta<0` 并标记已处理 |
| 定位必失败 | 全屏截图前没聚焦，截到的是别的窗口 | `locate()` 先 `ensure_focus()` 再截图 |
| 定位失败即放弃 | — | 回落到上次保存的区域 |
| 游戏没开 → 每 240 帧"撞死"一次（假死亡污染统计） | 空转被当成死亡 | 新增 `wait_for_game()`：轮询直到感知真看到游戏元素 |

## 五、Phase 2：扩展到 GTA5 要补什么

`GTA5Adapter` 已留占位，接入只需实现 `locate/grab/perceive/act` 四个方法，
`orchestrator` / `system1` / `system2` **一行不用改**。差距与补法：

| 维度 | dino | GTA5 | 要补 |
|---|---|---|---|
| 可观测性 | 完全可观测 | 3D、遮挡、HUD 干扰 | 3D 场景理解：YOLOE 开放词汇检车辆/行人/目标 + 小地图/深度融合 |
| 动作空间 | 2 个离散（跳/蹲） | 连续（转向/油门/射击/视角） | System1 残差改为预测**连续控制补偿量** |
| 奖励 | 二元稠密（活/死） | 稀疏（任务完成） | 任务状态机 + 目标进度记忆（接 CodePal X memory） |
| System2 职责 | 教会 S1 何时跳 | 任务分解、导航规划、战术选择 | 提示词与经验结构扩展为"任务级" |
| 时序 | 单步反应 | 长程依赖 | 情节记忆 + 长程规划 |
